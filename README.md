# 出海企业落地里程碑

追踪人工智能企业与东盟伙伴从场景对接会的合作意向，到本地试点、验收与正式合同的真实落地过程。榜单名次和一次握手不能证明项目落地——本资料只承认带授权证据的里程碑。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例，`src/domain.js` 在读取时执行结构与领域规则校验。当前参与方包括人工智能企业、东盟本地合作伙伴、活动运营机构、市场准入顾问。

资料所依据的领域事实：

- 榜单按六类应用场景（跨境商贸、智慧城治、医疗健康、智能制造、数字金融、绿色低碳）遴选企业
- 活动帮助企业对接多个东盟国家商业代表，新加坡、马来西亚、泰国等市场在数据许可、本地伙伴、试点场地与验收口径上各不相同
- 同一企业可就同一产品在多个国家并行推进；试点成果按国家分别归属，不得重复申报

## 建档口径

最小建档单位是「企业 × 目标国家」的一份合作档案（engagement），逐国记录九类事项：

1. **产品能力与适用场景** — 能做什么、对应当地什么场景
2. **合作方尽调** — 待办/通过/附条件通过/未通过，附尽调结论
3. **试点协议** — 签署日期、试点场地、范围、验收口径（验收标准写入协议，避免事后争议）
4. **数据使用范围** — 许可依据、允许用途、限制、跨境传输安排
5. **本地化事项** — 语言、本地日历、地名与行业词表等
6. **监管前置条件** — 逐项 pending/resolved；已解决必须附授权证据
7. **里程碑证据** — 意向登记、尽调完成、协议签署、试点启动、中期报告、验收通过、合同签署
8. **异常记录** — 见下
9. **商业转化** — 无/商机/谈判中/已签约，合同须可回溯到验收

### 异常必须留痕

以下五类异常都要记录发生日期与原因，档案不允许「静默变化」：合作方更换、范围缩减、试点暂停、验收争议、意向失效。意向失效（lapsed）档案保留失效原因，且不得登记任何试点成果。

### 阻塞的两种性质

- **市场准入受阻（market_access）**：必须挂起具体的未决监管前置条件（如数据许可、器械注册），由主办方转介市场准入顾问持续跟进；
- **单纯没有跟进（followup_gap）**：无任何在办监管或许可事项，仅因企业或客商未再接触。

存在未决前置条件的档案不得标为「没有跟进」，两类数字在主办方报表中分开统计。

### 证据授权与归属

- 每份材料登记授权状态：已授权 / 受限授权 / 不分享；里程碑与监管事项只能引用前两类。
- 每份材料有唯一归属档案；除对接会意向登记这类活动层级证据外，其他档案不得引用，从结构上杜绝同一试点成果在多国或多企业间重复申报。

## 各方权责

- **企业**：维护九类事项，只分享获授权的进度材料；范围或伙伴变化时主动登记异常。
- **本地伙伴**：在进入试点前逐项确认自身责任（部署运维、合规共同申请、场地协调等），尽调结论存档。
- **主办方（活动运营机构）**：从初步意向一直追到试点、验收与合同，凭证据而非名次认定落地，并区分市场准入问题与跟进缺口。
- **市场准入顾问**：对挂起的监管前置条件提供专业支持，验收争议时可推荐独立复核人。

## 本地校验

运行 `npm test`。校验覆盖：档案唯一性、证据授权与归属（防重复申报）、尽调与伙伴责任前置、里程碑顺序、合同先于验收的禁止、异常原因完整性、意向失效留痕、阻塞分类与前置条件挂起、监管事项证据要求。仓库不保存账号、密钥、连接串或真实身份信息。
